description: 專案啟動：盤點起點、建立 repo 骨架與 GitHub tracker，接著交棒給 grill-me
argument-hint: [目標資料夾路徑]
---

啟動一個新專案。目標資料夾：$1（未給就先問，不要自己選）。

依序執行，**每一步做完停下來回報，不要一路衝到底**：

1. **確認落點與起點**
   - 確認 $1 存在或可建立；若已有內容，列出來給使用者看過再動。
   - 問清楚：專案名稱、一句話目的、技術棧（Python / 其他 / 先不定）。
   - 問清楚這是**從零開始**還是**重做一個已經存在的系統**。兩者的第一步不同，答錯會讓後面幾步問錯問題。

2. **重做既有系統才做：盤點舊證據與信任邊界**（從零開始就跳過）
   - 前身留下的東西分三類：**可用的事實**（資料、語料、設定快照）、**只可參考的方法教訓**、**不可採信的結論**。
   - 一份結論作廢過，同一批數據上的其他結論預設也不採信——除非說得出它們為什麼不受同一個原因影響。
   - 把盤點結果寫成一份文件（例如 `docs/legacy/README.md`），列出每一類各有什麼、信任邊界劃在哪、為什麼。
   - 這一步做完才回到正常流程。跳過它的話，需求訪談會建立在沒人檢查過的前提上。

3. **建立骨架**
   - 使用 Skill `project-bootstrap`。
   - 完成後列出實際產生的檔案樹給使用者確認。

4. **交棒**
   - 骨架就緒後停下，告訴使用者下一步：`software` profile 是 `/grill-me` 把需求問到收斂，再由 `/to-spec` 發成 GitHub Issue；`experimental` profile 是 `/evidence-review` 先看證據，再 `/experiment-design` 凍結 Contract。
   - **不要自己開始訪談，也不要自己寫規格。** 那是後續技能的職責。

規範以目標專案的 `AGENTS.md` 為準。
