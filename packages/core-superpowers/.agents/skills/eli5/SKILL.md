# eli5

對面前這個人來說，這件事現在是一團霧。你的工作是給他一個**他能自己覆述**的心智模型，不是把正確的句子講完。

正確但沒有被理解的解釋等於沒解釋。這個技能管的是「怎麼講才會懂」；句子怎麼寫由 `asd-ste100` 管，兩者疊在一起用。

## 先寫下這三件事

動筆前先答，答不出來就先問使用者：

1. **他現在有什麼？** 他已經懂、而且跟這件事有關的具體東西。
2. **他缺的是哪一塊？** 不是「他不懂 X」，是「他不知道 A 跟 B 之間有關係」這種具體缺口。
3. **他要拿這個理解去做什麼？** 判斷一個決定、看懂一份錯誤訊息，還是只是好奇。用途決定要講到多深。

## 支點

類比的支點要挑他**已經摸過的具體東西**——排隊、鑰匙、收據、抽屜。不要用另一個技術概念當支點（「就像 message queue 一樣」對不懂 queue 的人是零資訊）。

**每個類比都要說出它在哪裡不成立。** 類比幫人上手，也會偷渡錯誤的直覺。給了支點就補一句「但這裡不一樣：⋯⋯」，那一句常常比類比本身更有價值。

## 三層推進

照這個順序，每一層都完整可停：

1. **一句話**：這是什麼、解決誰的什麼問題。
2. **一段話**：它怎麼運作，只講主線，分支全部先砍掉。
3. **我剛剛省略了什麼**：誠實列出被你簡化掉的部分，並說明什麼時候那些會變重要。

第 3 層是這個技能跟「講得含糊」的分界。省略沒問題，假裝沒省略才有問題。

## 需要圖的時候

只有在「東西之間的關係」比「東西本身」更難懂時才畫。畫法沿用 `diagram-design`：純文字 ```text 區塊、箭頭上要有動詞、不引入新的 renderer 依賴。一張圖回答一個問題。

## 不要做的事

- **不要用還沒解釋的術語。** 術語第一次出現時，白話在前、術語在後：「⋯⋯這種東西叫 idempotent」。
- **不要為了簡單而講錯。** 講不清楚就說「這裡我簡化了，實際上還有 X」，不要把兩個不同的東西抹平成一個。
- **不要堆比喻。** 一個貫穿到底的類比，勝過三個各講一半的。
- **不要從歷史或分類講起。** 從「他現在卡在哪」講起。

## 什麼時候算講完

兩個判準同時成立：

- 他能用**自己的話**覆述，而且沒有把你的類比當成事實本身。
- 他說得出**一個這個模型會失效的情況**——知道邊界在哪，才是真的懂了，而不是背下來。

達不到就回到「他缺的是哪一塊」重寫，不要把同一段話講得更大聲。
