# React web route

Use this route for React, Next.js, Vite, Tailwind, and shadcn/ui projects. Preserve the installed package manager and component conventions.

## Route by product type

- Landing/marketing: use [21st.dev](https://21st.dev/), [HeroUI Pro](https://heroui.pro/), or [Watermelon UI](https://ui.watermelon.sh/home) to study whole-page structure before choosing components.
- SaaS/dashboard/AI product: prioritize dense product patterns from HeroUI Pro, Watermelon UI, and 21st.dev over decorative landing-page defaults.
- Interaction polish: consider [beUI](https://beui.dev/) for source-owned React motion components and [Fluid Functionalism](https://www.fluidfunctionalism.com/) for interaction ideas.
- 3D/creative hero: use [ThreeUI](https://threeui.com/) only when 3D or shader work supports the concept and the performance budget.
- shadcn/Tailwind theming: use [tweakcn](https://tweakcn.com/) after confirming the project uses that stack.

## Installed Skills

- Use `21st-ui-explore` to search for references, `21st-ui-build` to implement, `21st-cli-use` for exact CLI operations, and `21st-ui-review` for a focused result check.
- Use `21st-ai` only when generation/iteration via 21st is desired. Treat `21st-design-sync` and `21st-registry` as publishing workflows; never publish, edit, or delete remote content without explicit authorization.
- Use `beui` before inventing a motion-heavy React component.
- Use the relevant GSAP Skill only after [motion.md](motion.md) selects GSAP.

## Implementation bar

- Reuse existing components and tokens; do not mix multiple visual systems on one page.
- Keep semantic HTML, keyboard access, focus visibility, responsive states, and content hierarchy intact.
- Prefer CSS or the project's current motion library for simple state transitions.
- Confirm dependency versions and licenses before adding code from registries or paid references.
