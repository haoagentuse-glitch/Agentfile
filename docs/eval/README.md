# Eval Set

比較 skill、Graphify、memory 策略等改動時，用這裡的任務量，不只憑架構看起來合理判斷。手動跑、手動記錄——先不建自動化，等真的重複跑到覺得煩才考慮工具化。

## 代表任務

以下四項都是這包實際發生過的任務類型，不是憑空編的假設：

1. **跨檔追蹤一個過時設定**：某處改動後，另一個檔案殘留過時說法，找出並修到唯一說法一致。
2. **安全評估並安裝一個外部 CLI 工具**：來源不只一個候選，要在「星數／維護活躍度／依賴輕重／有無資料外送」之間做取捨並裝好、驗證能用。
3. **記錄一個難逆決定**：兩個真實替代方案中選一個，寫成通得過 ADR 三條件測試（難逆、無上下文會意外、真的有取捨）的 ADR。
4. **解掉一個 SSoT 重複**：同一件事被兩個以上檔案各自描述，合併成一個擁有者、其餘連結過去。
5. **跨檔探索一個結構性問題**：例如「這個函式的呼叫者有哪些」「改這個型別會影響哪些檔案」，分別記錄只用 `rg`／整檔讀 vs（Graphify 啟用後）查圖兩種跑法的讀檔數與 token 差異——這項是 ADR 0004 啟用門檻要看的實測資料，Graphify 還沒裝之前，先跑 `rg`／整檔讀那組當 baseline。
